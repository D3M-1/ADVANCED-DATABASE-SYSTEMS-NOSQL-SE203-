المحاضرة 1 مقدمة إلى قواعد بيانات NoSQL نظري
🎯 دورة حياة تصميم قواعد البيانات

قبل اختيار أي نوع من قواعد البيانات يجب أن تمر بالمراحل الثلاث التالية:

  • الاستقصاء (Investigation): تحديد متطلبات البيانات والمستخدمين والعمليات.
  • التصميم (Design): رسم مخطط البيانات (ERD) وتحديد العلاقات والقيود.
  • التنفيذ (Implementation): بناء قاعدة البيانات الفعلية وملؤها بالبيانات.

💡 ملاحظة خبير: مرحلة التصميم هي الأهم — أي خطأ هنا يُكلّف جهدًا مضاعفًا لاحقًا. خذ وقتك في رسم ERD واضح قبل كتابة أي كود.

⚠️ مشاكل قواعد البيانات العلائقية (Relational)
  • الخاصية متعددة القيم (Multivalued Attribute): مثل موظف لديه أكثر من رقم هاتف — في SQL يحتاج جدولًا إضافيًا، أما في NoSQL فيُخزَّن كـ Array مباشرةً.
  • محدودية التوسع الأفقي (Scaling Limitations): SQL يصعب توزيعه على عدة خوادم (Horizontal Scaling)، بينما NoSQL صُمِّم لهذا الغرض أصلًا.
  • البيانات غير المنظمة: السجلات الطبية، الصور، السجلات الاجتماعية — صعبة الجدولة في SQL.
🗂️ أنواع قواعد بيانات NoSQL الأربعة
النوعالوصفمثالحالة استخدام
Key-Valueكل سجل هو مفتاح وقيمةRedis, DynamoDBتخزين الجلسات، الكاش
Documentمستندات JSON مرنةMongoDB, Couchbaseتطبيقات الويب، كتالوجات
Wide-Columnجداول بأعمدة مرنةCassandra, HBaseبيانات ضخمة، IoT
Graphعقد وحواف (العلاقات محورية)Neo4j, Amazon Neptuneالشبكات الاجتماعية
🍃 لماذا MongoDB؟
  • تخزين البيانات في مستندات BSON (Binary JSON) — أسرع من JSON النصي.
  • مخطط مرن (Schemaless): لا حاجة لتعريف الأعمدة مسبقًا.
  • قابلية التوسع الأفقي عبر Sharding — توزيع البيانات على عدة خوادم.
  • دعم النسخ المتماثل (Replication) — ضمان الاستمرارية.
  • يستخدم لغة استعلام شبيهة بـ JavaScript — سهل على مطوري الويب.
🏆 توصية الخبير

MongoDB هو الخيار المثالي لتطبيقات الويب الحديثة (MEAN Stack / MERN Stack) لأنه يتحدث "لغة JSON" كما يفعل JavaScript — مما يجعل البيانات تتدفق بسلاسة من قاعدة البيانات إلى الواجهة الأمامية بدون تحويلات معقدة.

المحاضرة 2 إعداد MongoDB Atlas السحابي إعداد
☁️ ما هو MongoDB Atlas؟

MongoDB Atlas هو الخدمة السحابية الرسمية لـ MongoDB — تتيح لك إنشاء قاعدة بيانات في السحابة مجانًا دون الحاجة لتثبيت أي شيء على جهازك.

✅ الطبقة المجانية M0: تمنحك 512 MB مجانًا — كافية تمامًا للتعلم ومشاريع الكورس.

🔧 خطوات الإعداد
  1. اذهب إلى mongodb.com/cloud/atlas وأنشئ حسابًا مجانيًا.
  2. اختر Create a Free Cluster ← الطبقة M0 (مجانية).
  3. اختر مزود السحابة: AWS والمنطقة: Bahrain (me-south-1) — الأقرب للمنطقة العربية.
  4. في Security Quickstart: أنشئ مستخدمًا وكلمة مرور لقاعدة البيانات.
  5. في Network Access: أضف عنوان IP الخاص بك أو اختر 0.0.0.0/0 للسماح لأي IP (للتعلم فقط).
  6. في Load Sample Dataset: حمّل بيانات تجريبية جاهزة للاستكشاف الفوري.

⚠️ تحذير أمني: في بيئات الإنتاج الحقيقية لا تستخدم 0.0.0.0/0 أبدًا — قيّد الوصول بعناوين IP محددة فقط.

🔗 نسخة Connection String

بعد إنشاء الـ Cluster ستحصل على رابط الاتصال:

Connection String 
mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/<dbname>
المحاضرة 3 MongoDB Compass وVS Code أدوات
🧭 MongoDB Compass

Compass هو واجهة رسومية (GUI) تتيح لك التعامل مع MongoDB بدون كتابة أوامر نصية. تنزيله مجاني من mongodb.com/products/compass.

  • تصفح المجموعات (Collections) والمستندات (Documents) بشكل بصري.
  • تشغيل الاستعلامات وعرض النتائج كجدول أو JSON.
  • تحليل هيكل البيانات وعرض الإحصاءات الفورية.
  • استيراد وتصدير البيانات (JSON, CSV).

💡 نصيحة: استخدم Compass في البداية لفهم هيكل البيانات بشكل بصري، ثم انتقل إلى كتابة الأوامر مباشرة — هذا التسلسل يبني الفهم بشكل أعمق.

💻 إضافة MongoDB في VS Code
  1. افتح VS Code → Extensions (Ctrl+Shift+X).
  2. ابحث عن "MongoDB for VS Code" من MongoDB Inc. وثبّتها.
  3. من شريط النشاط اليساري اضغط على أيقونة MongoDB.
  4. انقر "Add Connection" والصق Connection String من Atlas.
  5. يمكنك الآن تشغيل استعلامات MongoDB مباشرةً داخل VS Code!
🏆 توصية الخبير

الجمع بين Atlas + Compass + VS Code هو الثلاثي الذهبي للتطوير. Atlas لتخزين البيانات في السحابة، Compass للاستكشاف البصري، وVS Code لكتابة الكود — كل أداة في مكانها المثالي.

المحاضرة 4 JSON — الصيغة والمعايير الدولية نظري
📄 ما هو JSON؟

JSON (JavaScript Object Notation) هو تنسيق نصي لتبادل البيانات — خفيف، قابل للقراءة البشرية، ومستقل عن لغة البرمجة. أصبح المعيار الأكثر استخدامًا لتبادل البيانات بين التطبيقات.

📐 قواعد صياغة JSON
  • البيانات تُكتب في أزواج "مفتاح": قيمة
  • المفاتيح دائمًا بين علامات تنصيص مزدوجة "key"
  • الكائنات محاطة بـ أقواس معقوفة { }
  • المصفوفات محاطة بـ أقواس مربعة [ ]
  • القيم تُفصل بفاصلة , (لا فاصلة بعد آخر عنصر)
  • حساسة لحالة الأحرف: "Name" ≠ "name"
🔢 أنواع البيانات الستة في JSON
النوعمثالملاحظة
String"أحمد"نصوص بين علامات تنصيص
Number25 أو 1500.5بدون تنصيص، يشمل الأعداد العشرية
Booleantrue / falseبالأحرف الصغيرة دائمًا
Array["Java", "Python"]قائمة مرتبة من القيم
Object{"city": "Cairo"}كائن متداخل
Nullnullيمثل قيمة فارغة أو غير معروفة
📝 مثال عملي: مستند موظف
JSON 
{
  "ssn": "1234",
  "fname": "Ahmed",
  "lname": "Ali",
  "dno": 5,
  "salary": 25000,
  "gender": "M",
  "address": {
    "city": "Cairo",
    "street": "Tahrir Square"
  },
  "phones": ["+201001234567", "+201112345678"],
  "isManager": false,
  "joinDate": "2020-03-15"
}

✅ لاحظ: حقل phones هو مصفوفة — مشكلة "الخاصية متعددة القيم" في SQL محلولة بسطر واحد في MongoDB!

🌐 معايير JSON الدولية
  • RFC 7159 / ECMA-404: المعيار الرسمي لصياغة JSON.
  • Google JSON Style Guide: مرجع محترف لكتابة JSON بشكل موحد في المشاريع الكبيرة.
  • noBackend Architecture: نمط معماري يستخدم JSON API مباشرةً دون Middleware.
المحاضرة 5 عوامل الاستعلام — Query Operators نظري
🔍 عوامل المقارنة (Comparison Operators)
العاملالمعنىمثال
$gtأكبر من (greater than){salary: {$gt: 5000}}
$gteأكبر من أو يساوي{age: {$gte: 18}}
$ltأصغر من (less than){price: {$lt: 100}}
$lteأصغر من أو يساوي{dno: {$lte: 5}}
$neلا يساوي (not equal){gender: {$ne: "M"}}
$eqيساوي (equal) — الافتراضي{dno: {$eq: 8}}
🔗 عوامل منطقية (Logical Operators)
MongoDB — $or و $and 
// $or: موظفون في قسم 5 أو راتبهم أكبر من 30000
db.employee.find({
  $or: [
    {"dno": 5},
    {"salary": {$gt: 30000}}
  ]
})

// $and: موظفون في قسم 8 وجنسهم ذكر
db.employee.find({
  $and: [
    {"dno": 8},
    {"gender": "M"}
  ]
})

// الاختصار لـ $and (الكتابة المدمجة)
db.employee.find({"dno": 8, "gender": "M"})

💡 اختصار مفيد: عند استخدام $and على حقول مختلفة يمكنك كتابة الشرطين في نفس الكائن مباشرةً — MongoDB يفهمها كـ AND تلقائيًا.

📦 عوامل المصفوفات (Array Operators)
العاملالمعنىمثال
$inالقيمة ضمن قائمة{dno: {$in: [4, 5, 7]}}
$ninالقيمة ليست في القائمة{dno: {$nin: [1, 2]}}
$allالمصفوفة تحتوي كل القيم{skills: {$all: ["Python","Java"]}}
$notعكس الشرط{salary: {$not: {$gt: 5000}}}
❓ عامل الوجود (Existence Operator)
MongoDB — $exists 
// البحث عن المستندات التي يوجد فيها حقل "supervisor"
db.employee.find({"supervisor": {$exists: true}})

// البحث عن التي لا يوجد فيها الحقل
db.employee.find({"supervisor": {$exists: false}})
🏆 قاعدة ذهبية لكتابة الفلاتر

الصيغة الصحيحة دائمًا: {"field": {$operator: value}} — المفتاح اسم الحقل، والقيمة كائن يبدأ بـ $. أي فلتر لا يتبع هذه الصيغة خاطئ بالضرورة.

عملي 4 عمليات CRUD الأساسية عملي
➕ إدخال البيانات
MongoDB — Insert 
// إنشاء مجموعة جديدة
db.createCollection("employee")

// إدراج مستند واحد
db.employee.insertOne({
  "ssn": "1234",
  "fname": "Ahmed",
  "lname": "Ali",
  "dno": 5,
  "salary": 25000,
  "gender": "M"
})

// إدراج عدة مستندات
db.employee.insertMany([
  {"ssn": "5678", "fname": "Sara", "dno": 8, "salary": 30000, "gender": "F"},
  {"ssn": "9012", "fname": "Omar", "dno": 5, "salary": 22000, "gender": "M"}
])
✏️ تحديث البيانات
MongoDB — Update 
// $set: تعديل قيمة حقل موجود أو إضافة حقل جديد
db.employee.updateMany(
  {"dno": 5},                        // شرط التصفية
  {$set: {"salary": 28000}}          // التعديل
)

// $unset: حذف حقل من المستند
db.employee.updateMany(
  {},                                // {} = جميع المستندات
  {$unset: {"supervisor": ""}}
)

// تحديث بشرط مركب
db.employee.updateMany(
  {$or: [{"dno": {$gte: 14, $lte: 16}}, {"salary": 25000}]},
  {$set: {"join_date": ""}}
)

⚠️ تحذير: استخدام {} كفلتر يُطبّق التعديل على جميع المستندات في المجموعة — تأكد دائمًا من الفلتر قبل التنفيذ.

عملي 5 الفهارس · الحذف · الإسقاط · الترتيب عملي
📑 الفهارس (Indexes)

الفهرس يُسرّع عمليات البحث بشكل كبير — كفهرس الكتاب. بدون فهرس، MongoDB تبحث في كل المستندات (Full Collection Scan).

MongoDB — Indexes 
// إنشاء فهرس بسيط (1 = تصاعدي، -1 = تنازلي)
db.project.createIndex({"pnumber": 1})

// فهرس مركب باسم مخصص
db.project.createIndex(
  {"pnumber": 1, "Pname": -1},
  {"name": "pno_name"}
)

// فهرس فريد (Unique Index) — يمنع التكرار
db.employee.createIndex(
  {"ssn": 1, "fname": -1},
  {"name": "emp_name", "unique": true}
)

// عرض جميع الفهارس
db.project.getIndexes()

// حذف فهرس بالاسم
db.project.dropIndex("pno_name")
🏆 توصية الخبير — متى تستخدم الفهارس؟

أضف فهارس على الحقول التي تُستخدم كثيرًا في الفلاتر والترتيب. لكن لا تبالغ — كل فهرس يستهلك مساحة ويُبطئ عمليات الإدراج. القاعدة: فهرس واحد لكل حقل يُستعلم عنه بشكل متكرر.

🗑️ الحذف (Delete)
MongoDB — Delete 
// حذف مستند واحد (الأول الذي يطابق الشرط)
db.sales.deleteOne({"_id": 1})

// حذف مستندات متعددة
db.sales.deleteMany({"_id": {$lte: 5}})

// حذف جميع المستندات (احذر!)
db.sales.deleteMany({})
🎯 الإسقاط (Projection)

Projection يُحدد الحقول التي تريد إظهارها أو إخفاءها في النتائج. 1 = أظهر، 0 = أخفِ.

MongoDB — Projection 
// إظهار fname و lname فقط (وإخفاء _id)
db.employee.find(
  {"dno": 8},                              // الفلتر
  {"_id": 0, "fname": 1, "lname": 1}      // الإسقاط
)

// إخفاء حقل salary فقط
db.employee.find({}, {"salary": 0})
📊 الترتيب والحد والعدّ
MongoDB — Sort · Limit · Count 
// ترتيب تصاعدي (1) أو تنازلي (-1)
db.employee.find({"dno": 8}).sort({"salary": -1})

// تحديد عدد النتائج
db.employee.find({"dno": 8}).limit(5)

// تخطي نتائج (للصفحات)
db.employee.find().skip(10).limit(5)

// عدّ المستندات
db.employee.find({"dno": 8}).count()
// أو
db.employee.countDocuments({"dno": 8})

// الجمع بين الكل
db.employee.find(
  {"dno": 8},
  {"fname": 1, "salary": 1, "_id": 0}
).sort({"salary": -1}).limit(3)
المحاضرة 6 إطار التجميع — Aggregation Framework متقدم
🔄 ما هو Aggregation Pipeline؟

Pipeline التجميع يُعالج المستندات عبر سلسلة من المراحل (Stages) — كل مرحلة تُحوّل البيانات وتُمرّرها للمرحلة التالية. مكافئ لـ GROUP BY + HAVING في SQL.

📊 أولًا: التجميع الأساسي بـ $group
MongoDB — $group 
// متوسط الرواتب لكل قسم
db.employee.aggregate([
  {$group: {
    _id: "$dno",
    avgSalary: {$avg: "$salary"},
    maxSalary: {$max: "$salary"},
    minSalary: {$min: "$salary"},
    totalSalary: {$sum: "$salary"},
    count: {$sum: 1}
  }}
])
الدالةالمعنى
$avgالمتوسط الحسابي
$sumالمجموع (أو $sum: 1 للعدّ)
$maxأكبر قيمة
$minأصغر قيمة
🔗 ثانيًا: التجميع حسب حقول متعددة
MongoDB — $group متعدد 
// التجميع حسب القسم والجنس معًا
db.employee.aggregate([
  {$group: {
    _id: {dno_id: "$dno", gender_id: "$gender"},
    totalSalary: {$sum: "$salary"}
  }}
])
🎯 ثالثًا: $match قبل $group (فلترة البيانات)
MongoDB — $match + $group 
// الأقسام التي يزيد موظفوها عن 4 (يعادل HAVING في SQL)
db.employee.aggregate([
  {$group: {
    _id: "$dno",
    count: {$sum: 1}
  }},
  {$match: {"count": {$gt: 4}}}
])

💡 ترتيب المراحل مهم: $match قبل $group = فلترة المستندات الأصلية (WHERE). $match بعد $group = فلترة نتائج التجميع (HAVING).

🔀 رابعًا: $sort مع $group
MongoDB — $sort + $group 
// ترتيب الأقسام حسب _id تصاعديًا
db.employee.aggregate([
  {$group: {_id: "$dno", avgSal: {$avg: "$salary"}}},
  {$sort: {"_id": 1}}   // 1 = تصاعدي، -1 = تنازلي
])
🔗 خامسًا: $lookup (يعادل LEFT OUTER JOIN)
MongoDB — $lookup 
// ربط الموظفين بأقسامهم
db.employee.aggregate([
  {$lookup: {
    from: "department",      // اسم المجموعة الأخرى
    localField: "dno",       // حقل الربط في المجموعة الحالية
    foreignField: "dnumber", // الحقل المقابل في المجموعة الأخرى
    as: "employee_dept"      // اسم الحقل الجديد (يُخزن كـ Array)
  }}
])
🏆 توصية الخبير

$lookup يُعيد البيانات المرتبطة كـ Array — استخدم $unwind بعده إذا أردت تحويل كل عنصر في المصفوفة إلى مستند منفصل، تمامًا كما تفعل JOIN في SQL.

📐 سادسًا: $project (الإسقاط بعد التجميع)
MongoDB — $project 
// إخفاء _id و date بعد الربط
db.employee.aggregate([
  {$lookup: {
    from: "department",
    localField: "dno",
    foreignField: "dnumber",
    as: "employee_dept"
  }},
  {$project: {"_id": 0, "date": 0}}
])

🔧 عمليات CRUD في بايثون
Python — CRUD مع PyMongo 
import pymongo

# إدراج
result = employees.insert_one({"ssn": "1234", "fname": "Ahmed", "dno": 5})

# الإدراج مع معالجة خطأ التكرار
try:
    employees.insert_many([
        {"ssn": "5678", "fname": "Sara"},
        {"ssn": "9012", "fname": "Omar"}
    ])
except pymongo.errors.BulkWriteError as e:
    print(f"Duplicate Key Error: {e.details}")

# تحديث
result = employees.update_many(
    {"dno": 5},          # الفلتر
    {"$set": {"salary": 28000}}  # التعديل
)
print(f"Modified: {result.modified_count}")

# حذف

🏆 الفرق بين JS وPython في الفهارس

في JavaScript تُمرر الحقول كـ Object مباشرة. في Python تُمررها كـ قائمة من tuples لأن Python dicts لا تضمن الترتيب في الإصدارات القديمة. استخدم دائمًا [("field", direction), ...] في PyMongo.

🎯 القواعد الأساسية للإجابة الصحيحة

📌 قاعدة الفلتر الصحيح: {"field": {$operator: value}} — المفتاح دائمًا بين تنصيص، والعامل يبدأ بـ $ داخل كائن.

🧩 أسئلة متكررة وإجاباتها
س: ما الفلتر الصحيح لـ $or مع $gte و $lte؟
{$or: [{"dno": {$gte:14, $lte:16}}, {salary:25000}]}
س: صيغة find الصحيحة للبحث بقسم معين؟
db.employee.find({"dno": 8})
س: صيغة insertOne الصحيحة؟
db.sales.insertOne({ "item": "abc", "price": "20"})
س: صيغة deleteOne الصحيحة؟
db.sales.deleteOne( {"_id": 1} )
س: صيغة createIndex مركب بالاسم؟
db.project.createIndex({pnumber:1, Pname:-1}, {name: "pno_name"})
س: صيغة sort تنازلي على الراتب؟
db.employee.find({"dno":8}).sort({"salary": -1})
س: $and مع حقلين بشرط واحد؟
db.employee.find({ $and:[{"dno": 8},{"gender": "M"}] })
س: updateMany مع $set و $or — أي "None of the above" صحيحة؟
d) None of the above — جميع الخيارات الأخرى غالبًا صحيحة

⚠️ تنبيه مهم لأسئلة "None of the above": عندما تظهر هذه الإجابة، تحقق بعناية — أحيانًا تكون جميع الخيارات أ، ب، ج صحيحة ومكافئة، فتكون "None of the above" هي الإجابة الوحيدة الخاطئة المنطقيًا!
